# Feature and workflow decisions

Map a concrete journey from trigger through handoffs to completion. At each step record what the user already knows, what must be supplied, and where a mistake becomes costly. Look for a duplicated decision before adding a new feature.

Compare improving the bottleneck, moving the action earlier, and removing its cause. For every substantial suggestion identify beneficiary, expected benefit, implementation tradeoff, and a signal that could disprove it. Preserve an escape path for exceptions.

When delivery includes a measured trial, define which cases count, who records the event, and how to interpret a period with no eligible cases.
