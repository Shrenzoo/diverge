# Designing a comparison

For each direction, write a private one-sentence hypothesis: “For this audience, changing this mechanism will improve this outcome because …”. If two differ only in styling, combine them. Stop generating once another idea could not reasonably change the decision or the cap is reached.

| Technique | Procedure | Example functional question |
| --- | --- | --- |
| First principles | Take the named artifact apart into the job, constraints, information, and decisions. Rebuild from the minimum. | Which grade information changes a student's next action? |
| Inversion | Remove the central interaction and find another way to deliver its benefit. | Could a digest eliminate inbox triage? |
| Cross-domain transfer | Name the source mechanism, map its moving parts, and identify where the analogy breaks. | A forecast lets students test scenarios, but a grade estimate must show uncertainty. |
| Constraint transformation | Tighten, reverse, or remove one **assumed** constraint. Check against the ledger. | What if onboarding had to fit inside the first useful task? |
| Opportunity expansion | Identify an adjacent unmet need. Estimate additional scope and keep it only if the original task depends on it. | An undo action can make bulk editing usable. A new reporting product can wait. |
| Simplification | Eliminate one handoff, state, screen, dependency, or choice. Walk through the resulting failure case. | Can a validated import preview replace a separate clean-up wizard? |
