# Investigating an open problem

State the observable failure, the desired change, and constraints on the repair. Trace upstream inputs and downstream effects. Separate symptoms from causes. Construct hypotheses that predict different observations, including one in which the apparent bottleneck is incidental.

For a slow search, compare input latency, query execution, and rendering. Measure at boundaries using the same dataset. Ask what would still be slow with a cached result. Run the cheapest test that would rule out a plausible cause, then change its owner. Respect privacy when inspecting traces.
