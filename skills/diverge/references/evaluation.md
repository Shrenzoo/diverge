# Choosing and checking a direction

Eliminate directions that fail a hard contract, access need, budget, or safety requirement. If a requirement itself blocks the goal, explain the conflict and seek a decision before changing it.

| Dimension | Evidence to compare |
| --- | --- |
| Intent alignment | Walk a representative user from the trigger to the desired outcome. |
| Originality | Identify the functional difference from the conventional baseline. |
| Usefulness | Show the saved decision, prevented error, or newly possible action. |
| Feasibility | Identify required data, integrations, time, and missing capabilities. |
| Simplicity | Count added steps, states, dependencies, and concepts. |
| Maintainability | Identify the layer that owns the invariant and who will operate it. |
| Accessibility | Walk the alternative input and recovery paths. |
| Risk | Examine a failure, its blast radius, and the cost of reversal. |
| Constraint compliance | Cite the contract that makes the candidate eligible. |

For close calls, record one short reason for each dimension that distinguishes the candidates. Prefer a small discriminating test over a weighted sum. If evidence is sparse, use the simpler reversible choice and state the uncertainty.
